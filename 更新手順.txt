ドノヘン？ v6.2 — 配点更新

v6のセキュリティ更新が適用済みの環境向けです。

1. Supabaseのゲーム用プロジェクトを開きます。
2. SQL Editor → New query を開きます。
3. 「ドノヘン_v6.2_配点更新SQL.txt」の全文を貼り付けてRunを押します。
   ZIP・GitHubでは supabase/update_v6_2_scoring.sql が同じ内容です。
4. ゲーム画面を全員が再読み込みします。
5. 新しい部屋、または試合終了後に再スタートしてゲームを開始します。

【新配点】
ぴったり10点、差1〜2は9点、3〜4は8点、5〜6は7点、7〜8は6点、
9〜10は5点、11〜12は4点、13〜14は3点、15〜16は2点、17〜18は1点、19以上は0点。
ヒント役は予想者の平均点を四捨五入します。

進行中の試合は終了まで旧配点を維持します。過去の得点は変更しません。
画面だけの更新では採点は変わりません。上記SQLの実行が必要です。
v6の本人確認・閲覧制限・回数制限・部屋の期限・自動削除設定は維持します。

新規環境は supabase/schema.sql に新配点を含みます。
v6未適用の既存環境は、先にREADMEのセキュリティ更新手順に従ってください。


ドノヘン？ v6 — セキュリティ修正版の適用

【必須：Supabase側の更新】
GitHub・Vercelの更新だけではDB側の脆弱性は閉じません。
今回のSQLと匿名認証の設定を必ず適用してください。旧版のSQLは以後実行しないでください。

1. プレイ中のゲームを終え、Supabaseでゲーム用のプロジェクトを開きます。
2. SQL Editor → New query を開きます。
3. 「ドノヘン_v6_セキュリティ更新SQL.txt」の全文を貼り付け、Runを押します。
   ZIP・GitHubでは supabase/update_v6_security.sql が同じファイルです。
4. Authenticationの設定で「Anonymous Sign-Ins（匿名サインイン）」を有効にして保存します。
   メール入力やパスワード入力の画面は追加されません。
   別アプリと共用のSupabaseプロジェクトの場合は、他テーブルのauthenticated向けポリシーも先に確認してください。
   匿名サインインのIP単位の制限は標準30回/時です。Rate Limitsで値を確認し、無制限にはしないでください。
5. SQL Editorで「ドノヘン_v6_自動削除SQL.txt」を新しいクエリとして実行します。
   pg_cronを有効にし、10分おきに期限切れの部屋を削除します。
   pg_cronが有効化できない場合は、SupabaseのExtensions / Cronから有効化して再実行してください。
6. supabase/verify_security.sql を実行します。
   protocolのversionが6、room_realtime_publishedがfalse、can_selectがすべてfalse、自動削除ジョブがactive=trueであることを確認します。
7. Vercelの最新版のデプロイ完了後、全員がゲームを再読み込みし、新しい部屋を作ります。

【移行時の注意】
旧ルームは公開ID以外の本人確認情報がないため、新しい認証に安全に引き継げません。
旧ルームは更新後アクセス不可になります。旧データは移行時に即時削除せず、期限に従って削除します。
新しい版で作った部屋では、同じブラウザーの再読込から本人として復帰できます。
同じブラウザープロファイルの通常タブは同じ匿名ユーザーです。複数人のテストには別端末、別ブラウザーまたはシークレットウィンドウを使ってください。

【今回の対策】
・署名付きJWTの本人IDと参加者IDを全APIで照合。
・テーブルの直接読み取り・書き込みをanon/authenticated/PUBLICから取り消し。
・部屋情報は本人確認済みのメンバーにだけ返す。
・正解・未発表の回答はそのラウンドの正当な対象者にだけ返す。
・操作用の内部関数・削除関数を一般利用者から実行不可にする。
・ルームコードを推測しにくい8文字の暗号学的乱数へ変更。
・作成は1人5回/10分、参加試行は10回/分、操作は60回/分、読み取りは180回/分。
・参加中の部屋は1人3つまで。同時稼働500部屋、全体の作成40回/分・参加300回/分の上限。
・失敗した参加や操作の試行も回数に含める。
・2時間使われていない部屋を無効化。利用中は期限を延ばすが、最長24時間。
・終了後の部屋は30分で無効化。全員が明示退出した場合は即時削除。
・失効後は定期削除前でもアクセス不可。削除時に回答・正解・所属情報も連動削除。
・入力の文字数、型、JSONの大きさをサーバーで検証。

【公開状態】
新画面は更新前のDBには接続せず、「現在更新中です」として新規参加を止めます。
ただし、DBの公開権限と旧APIの危険は、上記SQLを実行するまで残っています。
Supabase側への直接アクセス許可は得られていないため、こちらから設定変更・SQL実行は行っていません。

【残る運用上の注意】
多数のIPや多数の認証IDを使う分散攻撃を、アプリ内の制限だけで完全に防ぐことはできません。
広く一般公開する場合は、匿名認証へのCAPTCHA/Turnstileと、上流のWAF・利用量の監視も追加してください。
