# ドノヘン？ v5

ヒントから0〜100の位置を当てるオンラインパーティーゲームです。

## 遊び方

1. ニックネームを入力し、部屋を作るかルームコードで参加します。
2. 待機室でホストが「ヒント役は1人何回？」を1〜3回から選びます。
3. 総ラウンド数は、開始時の参加人数×選んだ回数です。2〜12人、最大36ラウンドに対応します。
4. ヒント役は正解の数字を見て言葉でヒントを出します。ほかの人は1回ずつ予想します。
5. ホストが答えを公開すると、今回の得点を最下位から発表します。最終結果も合計得点の最下位から発表します。

同点は同順位でまとめて表示します。発表中は「まとめて見る」でスキップできます。発表が終わるまで次のラウンド・再スタートはできません。ブラウザーの動きを減らす設定にも対応します。

## 得点

| 正解との差 | 得点 |
|---|---:|
| 0（ぴったり） | 5 |
| 1〜2 | 4 |
| 3〜4 | 3 |
| 5〜6 | 2 |
| 7〜8 | 1 |
| 9以上 | 0 |

ヒント役は予想者の平均得点を四捨五入した点数を獲得します。

## 今回の更新の適用

**公開済みのゲームでも、SupabaseのSQL更新が必要です。**

1. ゲームを終えてから、Supabaseのゲーム用プロジェクトでSQL Editorを開きます。
2. `supabase/update_v5.sql` の全文を新しいクエリに貼り付けて実行します。既存の部屋や回答は削除しません。
3. GitHubの変更がVercelへデプロイされていることを確認し、全員が画面を再読み込みします。
4. 新しい部屋、または再スタート後の待機室で回数を選んで開始します。

更新前から進行していた試合は元の5ラウンドを維持します。SQLを更新すると以降の採点は新配点になります。SQL未適用の場合、画面は旧版の5ラウンド・旧配点の説明を使い、回数選択は表示しません。回数選択が出ない場合はSQLの適用先を確認してください。

## 新規セットアップ

1. Supabaseでプロジェクトを作成し、`supabase/schema.sql` を全文実行します。
2. `.env.example` を `.env.local` にコピーし、次を設定します。

   ```env
   VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
   VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
   ```

   旧プロジェクトのanonキーは `VITE_SUPABASE_ANON_KEY` でも利用できます。secret / service_roleキーは使わないでください。
3. `npm.cmd install` → `npm.cmd run dev` で起動します。`npm.cmd run build` でビルドできます。
4. VercelではVite、ビルドコマンド `npm run build`、出力 `dist` を指定し、同じ環境変数を設定します。

## お題と復帰

- お題は `src/prompts.ts` の100種類。`お題一覧_100種類.md` と内容・順番が一致しています。
- 1ゲーム内では同じお題を再出題しません。ヒント役退出に伴う同一ラウンドのやり直しでは、お題を維持します。
- ヒント役の順番は開始時に確定します。途中退出した人の未実施の順番は除外し、残りラウンド数を調整します。ヒント役が退出したラウンドは残った人でやり直します。最後の担当者が退出し、次の担当がいない場合は残ったホストが引き継ぎます。
- 残り1人になると待機室に戻ります。次の開始時に得点・順番をリセットします。
- 同じブラウザーで再読み込みすると、localStorageの参加者IDで得点・回答・権限を再取得します。
- 発表完了はsessionStorageに保存し、同じタブの再読込では完了済みの演出を繰り返しません。
- 「退出する」は参加者を削除します。タブを閉じただけでは退出扱いになりません。
- ゲストID方式です。ブラウザーのデータ消去や別端末からの復帰には対応しません。
