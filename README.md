# ドノヘン？ v8

ヒントから0〜100の位置を当てるオンラインパーティーゲームです。

## 今回の更新（v7以降の環境）

SQL Editorで `supabase/update_v8_review.sql` を実行し、全員が再読み込みしてください。更新には完全一致15点の配点も含みます。進行中の試合の配点を維持します。

- 予想位置に「正解より＋／−いくつ」を表示します。完全一致は「ぴったり」、未回答は「時間切れ・未回答」と区別します。
- 待機室は「招待・メンバー」と「ゲームの設定」に整理。プレイ中は進行とお題を中心にし、メンバー・合計点を折りたたみました。
- 答え合わせは予想位置と得点を並べて表示し、スマホでは縦に表示します。ヒント役の得点は回答者の発表後、その下に分けます。
- 終了画面は「ランキング・表彰」と「振り返り」を切り替えます。振り返りでは各ラウンドのお題・ヒント・ヒント役・正解・予想・得点を確認できます。
- 記録はホストの答え公開時に保存します。未公開の正解・予想は履歴に入りません。退出した参加者の名前も発表時の状態で残します。
- 記録は同じ部屋の有効期限内でのみ利用でき、再スタートすると消去します。既存の過去ラウンドは補完しません。更新前の試合では記録のあるラウンド、記録がない場合は最後のラウンドだけを表示します。

表彰は従来の3種類を維持します。公開済みの部屋の情報を取得できるのは、本人確認済みの参加者だけです。

## 完全一致15点への更新（v7適用済み）

SQL Editorで `supabase/update_v7_1_exact_bonus.sql` を実行し、全員が再読み込みしてください。更新後に開始する試合から完全一致が15点になります。差1〜2の9点以下は変更しません。ヒント役の平均点にも15点を使います。進行中の試合は最後まで元の配点を維持します。

## 今回の更新（v6適用済みの環境）

SQL Editorで `supabase/update_v7_features.sql` を全文実行し、全員が再読み込みしてください。この最新版のv7更新SQLには完全一致15点の配点も含みます。旧更新SQLを後から実行しないでください。

- 予想位置：答え合わせで、正解と各人の予想を共通の0〜100の尺度に順次表示します。人数分の行を設け、同じ位置でも重ならないようにします。
- 招待リンク：待機室の「招待リンクをコピー」で共有します。開くとコードが入力済みになります。参加にはニックネームを入力して「参加する」を押します。認証情報をリンクに含めません。
- 回答時間：待機室でホストが「なし・30秒・60秒」を選択します。ヒント送信時に開始し、サーバーの時刻で判定します。全員回答済みなら早く終了します。期限後は次の状態取得時に発表待ちへ移り、未回答は0点です。ヒント役の平均にも未回答の0点を含めます。答えの公開は従来どおりホストが行います。
- 表彰：新しく開始する試合から集計します。「ぴったり賞」は完全一致数、「精度賞」は未回答のない人の平均誤差、「ヒント名人」はヒント役の平均得点で決め、同率は全員を表彰します。該当者がいない賞は表示しません。退出者は対象外です。
- ターンの発表：順位発表は回答者だけです。全員の発表後、ヒント役の得点をその下に表示します。最終ランキングは全員が対象です。

既存のゲームは継続できます。進行中のゲームでは過去の表彰データを補完せず、次のゲームから表彰を有効にします。時間設定は待機室でのみ変更できます。

## 配点について

更新後に開始するゲームは完全一致15点です。進行中のゲームは終了まで元の配点を維持し、過去の得点は変更しません。新しい部屋、または再スタートして次の試合を開始すると新配点になります。

## セキュリティ更新の適用

**GitHub・Vercelの更新に加えて、Supabaseの更新が必要です。**

1. プレイ中のゲームを終え、SQL Editorで `supabase/update_v6_security.sql` を実行します。
2. AuthenticationでAnonymous Sign-Insを有効にします。メール・パスワードの入力画面はありません。
3. `supabase/cleanup_schedule.sql` を実行し、10分ごとの期限切れデータ削除を設定します。
4. `supabase/verify_security.sql` で権限と削除ジョブを確認します。
5. 最新の画面を再読み込みし、新しい部屋を作ります。

旧ルームは安全に本人確認できないため引き継げません。旧版のSQLを再実行しないでください。詳細は `更新手順.txt` を参照してください。

## 新規セットアップ

1. Supabaseでプロジェクトを作成し、`supabase/schema.sql` を全文実行します。
2. 上記の匿名認証・自動削除・検証の設定を行います。
3. `.env.example` を `.env.local` にコピーして設定します。

   ```env
   VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
   VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
   ```

   旧anonキーは `VITE_SUPABASE_ANON_KEY` でも利用できます。secret / service_roleキーは使わないでください。
4. `npm install` → `npm run dev` で起動します。`npm run build` でビルドできます。Windowsでは `npm.cmd` も利用できます。
5. VercelではVite、ビルド `npm run build`、出力 `dist` と同じ環境変数を設定します。

## 遊び方と得点

ニックネームを入力して部屋を作るか、8文字のルームコードで参加します。2〜12人に対応し、ホストがヒント役を1人1〜3回から選びます。総ラウンド数は開始時の人数×回数、最大36ラウンドです。

ヒント役は正解を見て言葉でヒントを出し、ほかの人が予想します。

| 正解との差 | 得点 |
|---|---:|
| 0 | 15 |
| 1〜2 | 9 |
| 3〜4 | 8 |
| 5〜6 | 7 |
| 7〜8 | 6 |
| 9〜10 | 5 |
| 11〜12 | 4 |
| 13〜14 | 3 |
| 15〜16 | 2 |
| 17〜18 | 1 |
| 19以上 | 0 |

ヒント役は予想者の平均得点を四捨五入した点数を獲得します。ラウンドと最終結果は最下位からゆっくり発表し、同点はまとめて表示します。「まとめて見る」で省略でき、ブラウザーの動きを減らす設定にも対応します。

## お題・退出・復帰

- `src/prompts.ts` の100種類と `お題一覧_100種類.md` は内容・順番が一致します。1ゲーム内でお題は重複しません。
- 途中退出で担当順・残りラウンドを調整します。ヒント役が退出したラウンドは残った人でやり直し、お題を維持します。残り1人になると待機室に戻ります。
- 同じブラウザーでは匿名認証の保存情報を使って再読込から復帰します。ブラウザーのデータ消去や別端末への引き継ぎには対応しません。
- 通常の複数タブは同じ匿名ユーザーです。複数人のテストには別端末・別ブラウザー・シークレットウィンドウを使ってください。
- 「退出する」は参加者を削除します。タブを閉じただけでは退出扱いになりません。
- 部屋は2時間の未使用で失効し、利用中でも最長24時間、終了後は30分です。失効後は復帰できません。
- 発表完了は同じタブに保存し、完了済みの演出を再読込で繰り返しません。

## 保護と制限

APIはSupabaseが検証した認証IDと参加者IDを照合し、部屋のメンバーだけに情報を返します。テーブルの直接アクセスと内部関数の実行は一般利用者には許可しません。作成・参加・操作・読み取りの回数制限、1人3部屋と全体500部屋の上限があります。

分散攻撃を完全に防ぐものではありません。必要に応じてCAPTCHA・WAF・利用量監視を追加してください。別アプリとSupabaseを共用する場合は、そのアプリのauthenticated向け権限も確認してください。

検証範囲は `検証結果.txt`、適用手順と各制限値は `更新手順.txt` を参照してください。
