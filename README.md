# ドノヘン？ v10

ヒントから0〜100の位置を当てる、2〜12人のオンラインパーティーゲームです。

## 既存環境の更新

v9適用済みなら、Supabase SQL Editorで `supabase/update_v10_share.sql` を全文実行し、全員が再読み込みしてください。共有結果専用のテーブル・APIと削除処理を追加します。既存の部屋・得点・振り返りは維持します。

v7〜v8の環境は、先に最新版の `supabase/update_v9_results.sql` を実行してください。旧版のSQLを後から実行しないでください。

`supabase/verify_security.sql` で、テーブルの直接アクセスがすべて拒否され、内部関数の実行権限が公開されていないことを確認できます。匿名利用者が呼べるAPIはプロトコル確認と、本人が明示共有した結果の取得だけです。通常の部屋情報は本人確認済みの参加者だけに返します。

## 今回の変更

- 共有画像は自分の順位・得点と、自分がヒント役だった回のうち、回答者の実際の平均得点が最高だったお題・ヒントを表示します。平均が同じなら最初のラウンドを選び、未回答の0点も平均に含めます。
- 全員ランキングの共有、画像保存・投稿文コピーの単独ボタンは廃止しました。
- 「結果を共有する」でゲーム内の選択画面を開き、X・LINEの投稿／送信画面へ直接進みます。OSの共有候補にXが存在するかどうかに依存しません。
- SNSに取得できる結果ページと画像を用意し、画像付きリンクとして共有します。SNS側のプレビュー表示・キャッシュ更新は各サービスの判断に依存します。画像を投稿のメディア欄に自動添付する方式ではありません。
- 振り返りは全ラウンドを常時展開し、折りたたみ操作をなくしました。
- 既存の表彰3種類に、あなたにとっての「波長がぴったり」「すれ違いも楽しい」を追加。2人の位置の平均差が最小／最大の相手を表示します。ヒント役の位置は正解、回答者の位置はその人の予想として扱います。
- 相性は2回以上比較できる相手が対象です。未回答の回は比較から除外し、同率は全員表示します。平均が全員同じ、または相手が1人だけなら「すれ違いも楽しい」は出しません。実際の性格の相性を評価するものではありません。
- 完全一致に「ぴったり！」と金色の光・小さな紙吹雪の演出を追加。動きを減らす設定では演出を省略します。配点は変えません。
- ヒントが届くと短い通知音が鳴ります。右上の「♪ 音」でミュート・音量変更・試聴ができます。初期音量30%、設定は同じブラウザーに保存します。再読み込み時の古いヒントや同じ状態の再取得では鳴らしません。
- ランキングは1位を淡いゴールド、2位をシルバー、3位をブロンズ、その他を落ち着いた色にしました。自分の行には枠を付けます。

## 共有結果の公開範囲

共有画面を開くだけでは公開しません。XまたはLINEを選択したときに初めて、自分の結果画像・名前・順位・得点・ベストヒントを公開します。ルームコード・認証情報・他の参加者の名前や回答は含めません。

結果ページはランダムなトークンのURLで7日間参照できます。部屋が消えた後もこの期限内は共有結果を参照できます。ゲーム側では期限後に参照を拒否し、既存の10分ごとの削除ジョブで画像と記録を削除します。SNSに投稿済みの内容やSNS側のキャッシュは残る場合があります。

保存画像は1件450KBまで、同時200件まで、作成は1人1日3件まで・10分間に5回までです。同じ試合の共有は同じURLを再利用します。公開結果の読み取りは全体で1分間1200回までです。一般利用者は共有テーブルも直接読み書きできません。

Vercelには `api/share.js` を配置します。既存の `VITE_SUPABASE_URL` と `VITE_SUPABASE_PUBLISHABLE_KEY`（旧環境は `VITE_SUPABASE_ANON_KEY`）をサーバー側でも利用します。新しい秘密鍵やSNSのAPIキーは不要です。独自ドメインを明示する場合のみ `PUBLIC_SITE_URL` にHTTPSの公開URLを設定できます。

## 新規セットアップ

1. Supabaseでプロジェクトを作り、`supabase/schema.sql` を全文実行します。
2. AuthenticationでAnonymous Sign-Insを有効にします。
3. `supabase/cleanup_schedule.sql` で10分ごとの削除ジョブを設定します。
4. `.env.example` を `.env.local` にコピーして公開URLとpublishableキーを設定します。secret / service_roleキーは使用しません。
5. `npm install`、`npm run dev` で起動。`npm run build` でビルドします。Windowsでは `npm.cmd` も使えます。
6. Vercelへルートごとデプロイします。Vite、ビルド `npm run build`、出力 `dist` と上記環境変数を指定してください。`api/` と `server/` も含めて配置します。SNS用APIはVercelのNode.js関数として動作し、Viteの開発サーバー単体には含まれません。

## 遊び方と配点

ホストがヒント役を1人1〜3回、回答時間をなし／30秒／60秒から選びます。最大36ラウンド。お題100種類は1ゲーム内で重複しません。

| 正解との差 | 得点 |
|---|---:|
| 0 | 15 |
| 1〜2 | 9 |
| 3〜4 | 8 |
| 5〜6 | 7 |
| 7〜8 | 6 |
| 9〜10 | 5 |
| 11〜12 | 4 |
| 13〜14 | 3 |
| 15〜16 | 2 |
| 17〜18 | 1 |
| 19以上・未回答 | 0 |

ヒント役は回答者全員の平均点を四捨五入します。進行中の試合は開始時の配点を維持します。最終ラウンドの答え合わせ後、ホストが「最終結果を見る」でランキングへ進めます。

同じブラウザーで再読み込みから復帰できます。通常タブ同士は同じ匿名ユーザーです。複数人のテストには別端末・別ブラウザーを使ってください。部屋は未使用2時間、最長24時間、終了後30分で失効します。再スタートで前の振り返りは消えますが、明示共有した結果の期限は別です。

調査の根拠・検証範囲は `共有方式の調査.md` と `検証結果.txt` を参照してください。
